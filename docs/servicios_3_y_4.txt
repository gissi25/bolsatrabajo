SERVICIO 3: Sincronizacion de Perfiles de Postulantes
====================================================

Archivos:
  - Android: app/src/main/java/sv/ues/fia/eisi/bt/ui/servicios/Servicio3Fragment.kt
  - Servidor: servicio3.php
  - Ruta API: go.php?action=sincronizar_postulantes

A) En que consiste
------------------
Herramienta para recuperar todos los postulantes almacenados en la base de
datos local (SQLite del dispositivo Android) y subirlos al servidor remoto
InfinityFree (MySQL). Sube cada postulante con toda su informacion asociada:
formacion academica, experiencia laboral, certificaciones, habilidades y redes
sociales. El flujo es unidireccional: solo de local a remoto.

B) Tablas que toca
--------------------

LOCAL (SQLite) - Solo lectura:
  POSTULANTE                  - tabla principal con datos del postulante
  GENERO                      - nombre del genero
  TIPO_DOCUMENTO              - nombre del tipo de documento
  GRADO_ACADEMICO             - nombre del grado academico
  DEPARTAMENTO                - nombre del departamento (via distrito)
  MUNICIPIO                   - nombre del municipio (via distrito)
  DISTRITO                    - nombre del distrito
  FORMACION_ACADEMICA         - formaciones academicas del postulante
  OFERTA_ACADEMICA            - oferta asociada a la formacion
  INSTITUCION                 - nombre de la institucion
  EXPERIENCIA_LABORAL         - experiencias laborales del postulante
  EMPRESA                     - nombre de la empresa
  CERTIFICACION               - certificaciones del postulante
  TIPO_CERTIFICACION          - nombre del tipo de certificacion
  HABILIDAD_POSTULANTE        - habilidades del postulante
  HABILIDAD                   - nombre de la habilidad
  RED_SOCIAL_POSTULANTE       - redes sociales del postulante
  RED_SOCIAL                  - nombre de la red social

SERVIDOR (MySQL InfinityFree) - Escritura:
  POSTULANTE                  - INSERT o UPDATE
  DISTRITO                    - INSERT IGNORE (se crea si no existe)
  MUNICIPIO                   - INSERT IGNORE (se crea si no existe)
  DEPARTAMENTO                - INSERT IGNORE (se crea si no existe)
  FORMACION_ACADEMICA         - DELETE + INSERT (reemplazo completo)
  EXPERIENCIA_LABORAL         - DELETE + INSERT
  CERTIFICACION               - DELETE + INSERT
  HABILIDAD_POSTULANTE        - DELETE + INSERT
  RED_SOCIAL_POSTULANTE       - DELETE + INSERT

SERVIDOR (MySQL InfinityFree) - Solo lectura de validacion:
  GENERO                      - verificar que exista el ID_GENERO
  TIPO_DOCUMENTO              - verificar que exista el ID_TIPO_DOCUMENTO
  GRADO_ACADEMICO             - verificar que exista y no sea "bachiller"

C) Local vs Servidor
---------------------
Operacion                          | Lugar       | Tipo
-----------------------------------|-------------|----------
Lectura de todos los postulantes   | SQLite      | Local
Construccion de JSON por c/u       | SQLite      | Local
(5 subconsultas: formacion, exp,   |             |
certificacion, habilidad, redes)   |             |
Mostrar lista en RecyclerView      | Android UI  | Cliente
Mostrar dialogo de detalle         | Android UI  | Cliente
Validacion de edad >= 18           | MySQL       | Remoto
Validacion de grado no bachiller   | MySQL       | Remoto
Auto-creacion de distrito faltante | MySQL       | Remoto
INSERT/UPDATE transaccional        | MySQL       | Remoto

D) Flujo detallado
-------------------
1. El usuario abre la pantalla y ve dos botones: "Recuperar" y "Sincronizar".

2. Toca "Recuperar":
   a) La app abre SQLite y ejecuta: SELECT ID_POSTULANTE FROM POSTULANTE
   b) Por cada ID, ejecuta una consulta JOIN gigante que trae:
      - Datos del postulante + genero + tipo_documento + grado_academico
      - Datos de ubicacion (depto + municipio + distrito)
   c) Luego ejecuta 5 consultas independientes por postulante:
      - FORMACION_ACADEMICA (con OFERTA_ACADEMICA e INSTITUCION)
      - EXPERIENCIA_LABORAL (con EMPRESA)
      - CERTIFICACION (con TIPO_CERTIFICACION)
      - HABILIDAD_POSTULANTE (con HABILIDAD)
      - RED_SOCIAL_POSTULANTE (con RED_SOCIAL)
   d) Arma un JSONObject por postulante con toda la data anidada
   e) Muestra la lista en pantalla con resumen por tarjeta
   f) Habilita "Sincronizar" con el total: "Subir N postulante(s)"

3. Toca una tarjeta "Ver detalle":
   a) Dialogo con datos personales + listas formateadas de cada seccion

4. Toca "Sincronizar":
   a) Itera sobre cada postulante de la lista
   b) Por cada uno, llama a go.php?action=sincronizar_postulantes via POST
   c) El servidor PHP:
      - Valida fecha de nacimiento no futura y edad >= 18
      - Valida grado academico no sea "bachiller"
      - Valida que GENERO, TIPO_DOCUMENTO y GRADO_ACADEMICO existan
      - Si el distrito no existe, crea DEPARTAMENTO -> MUNICIPIO -> DISTRITO
      - Inicia transaccion MySQL
      - Si el postulante ya existe (por ID): hace UPDATE y reemplaza hijos
      - Si es nuevo: hace INSERT de todo
      - Por cada hijo: DELETE de todos los existentes + INSERT de los nuevos
      - Commit o Rollback
      - Retorna JSON: {"exito":true, "id_postulante":"...", "accion":"insertado"}
   d) Acumula contadores de insertados y actualizados
   e) Muestra dialogo final con resultados

E) Por que es util
-------------------
- Permite captura offline de datos: los postulantes se registran sin internet
  en SQLite, y un administrador sube todo en lote cuando hay conexion.
- Validacion centralizada: el servidor aplica reglas de negocio (edad, grado)
  que garantizan calidad de datos.
- Sincroniza todo el perfil (5 tablas hijas) en una sola transaccion,
  manteniendo integridad referencial.
- Util para ferias de empleo, quioscos o zonas sin conectividad.

F) Rol dirigido
----------------
Postulante (para crear su perfil) y Administrador (para subir lotes al servidor).

SERVICIO 4: Busqueda de Postulantes por Certificacion (ACTUALIZADO)
=====================================================================

Archivos:
  - Android: app/src/main/java/sv/ues/fia/eisi/bt/ui/servicios/Servicio4Fragment.kt
  - Servidor: servicio4.php
  - Rutas API: go.php?action=tipos_certificacion
               go.php?action=buscar_certificaciones
               go.php?action=sincronizar_certificaciones

A) En que consiste
------------------
Buscador de postulantes que poseen un tipo especifico de certificacion.
Los filtros son: tipo de certificacion (requerido), nombre (opcional) y
vigencia (Todos / Solo Vigentes / Solo Vencidos). La busqueda se realiza
contra el servidor InfinityFree, NO contra la base local. Los resultados
muestran el estado de cada certificacion (vigente/vencida) con su fecha de
vencimiento calculada. Ademas, hay un boton "Guardar resultados en local"
para descargar los datos del servidor a SQLite.

La fecha de vencimiento se calcula sumando la duracion de vigencia (en
anios, segun el tipo de certificacion) a FECHA_CERTIFICACION. Las
duraciones estan hardcodeadas en servicio4.php:

  Tipo                      | Duracion
  --------------------------|:--------:
  Certificacion Profesional | 5 anios
  Diplomado                 | 3 anios
  Curso                     | 3 anios
  Idioma                    | 3 anios
  Seminario                 | 1 anio

B) Tablas que toca
--------------------

LOCAL (SQLite) - Solo lectura:
  TIPO_CERTIFICACION          - fallback del dropdown de tipos (si no hay server)

LOCAL (SQLite) - Escritura (solo al tocar "Guardar en local"):
  POSTULANTE                  - INSERT OR IGNORE + UPDATE (upsert)
  CERTIFICACION               - INSERT OR IGNORE + UPDATE (upsert)

SERVIDOR (MySQL InfinityFree) - Lectura:
  TIPO_CERTIFICACION          - SELECT para llenar dropdown de tipos (con DURACION_VIGENCIA_ANIOS)
  POSTULANTE                  - SELECT con JOIN para busqueda
  CERTIFICACION               - SELECT con JOIN para busqueda
  GRADO_ACADEMICO             - JOIN para nombre del grado
  INSTITUCION                 - JOIN para nombre de la institucion

SERVIDOR (MySQL InfinityFree) - Escritura (NO se usa desde este servicio):
  (El endpoint sincronizar_certificaciones sigue existiendo para uso externo)

C) Local vs Servidor
---------------------
Operacion                           | Lugar       | Tipo
------------------------------------|-------------|----------
Cargar dropdown tipos (intento)     | MySQL       | Remoto
Cargar dropdown tipos (fallback)    | SQLite      | Local
Buscar postulantes por filtros      | MySQL       | Remoto
Calcular fecha vencimiento/vigencia | PHP         | Remoto
Mostrar resultados con badge        | Android UI  | Cliente
Guardar resultados en local (boton) | SQLite      | Local

D) Flujo detallado
-------------------
1. Al abrir la pantalla:
   a) Se cargan los tipos de certificacion en el dropdown (spinner)
   b) Intenta 3 veces (con 3s de espera) obtenerlos del servidor:
      GET go.php?action=tipos_certificacion
      -> SELECT ID_TIPO, NOMBRE_TIPO desde MySQL
      -> PHP agrega DURACION_VIGENCIA_ANIOS hardcodeado a cada tipo
   c) Si falla, lee desde SQLite local: SELECT de TIPO_CERTIFICACION
      (en ese caso, no hay informacion de vigencia)

2. El usuario selecciona:
   - Tipo de certificacion (requerido) - Spinner
   - Nombre de certificacion (opcional, texto LIKE %texto%) - campo de texto
   - Vigencia (requerido) - Spinner con opciones: "Todos", "Solo Vigentes", "Solo Vencidos"

3. Toca "Buscar":
   a) Valida que haya seleccionado un tipo
   b) Muestra ProgressBar y deshabilita boton
   c) Llama al servidor:
      GET go.php?action=buscar_certificaciones&tipo=X&nombre=Y&vigente=Z
   d) El servidor PHP:
      - Ejecuta query a MySQL con JOIN a POSTULANTE, CERTIFICACION,
        TIPO_CERTIFICACION, INSTITUCION, GRADO_ACADEMICO
      - Filtra por tipo (obligatorio) y nombre (opcional, LIKE)
      - NO filtra por anio (reemplazado por vigencia)
      - Por cada certificacion, calcula:
        aniosVigencia = vigenciaPorTipo[idTipo]
        fechaVencimiento = FECHA_CERTIFICACION + aniosVigencia
        vigente = fechaVencimiento >= hoy
      - Si el filtro es "vigentes", excluye certificaciones vencidas
      - Si el filtro es "vencidos", excluye certificaciones vigentes
      - Agrupa por postulante, ordena por cantidad de certificaciones
      - Retorna JSON con postulantes y certificaciones (cada una con
        fecha_vencimiento y estado vigente)
   e) Muestra resultados en RecyclerView con badge de estado:
      - "VIGENTE" (fondo verde) si todas las certificaciones estan vigentes
      - "VENCIDA" (fondo rojo) si alguna esta vencida
      - Muestra resumen: "N vigente(s), M vencida(s)"
   f) Aparece boton "Guardar resultados en local"

4. Toca "Guardar resultados en local":
   a) Recorre todos los postulantes del resultado
   b) Por cada uno, hace INSERT OR IGNORE + UPDATE en SQLite:
      - POSTULANTE: todos los campos (16 columnas), con FKs desactivadas temporalmente
      - CERTIFICACION: todas las certificaciones del postulante
   c) Muestra Snackbar "Resultados guardados en local"

5. Toca una tarjeta de resultado:
   a) Dialogo con datos personales (nombre, email, ID, grado)
   b) Lista de certificaciones con estado y fecha de vencimiento:
      "Certificado X — Instituto Y (2020) [VIGENTE - Vence el 2025-06-15]"
   c) Boton "Cerrar"
   (Ya no tiene boton "Sincronizar con servidor")

E) Por que es util
------------------
- Las empresas pueden buscar candidatos por certificacion especifica
  (ej: "Python", "Ingles", "Project Management") consultando datos reales
  del servidor.
- Cada certificacion muestra si esta vigente o vencida, con la fecha de
  vencimiento calculada segun el tipo de certificacion.
- Filtro de vigencia permite encontrar solo candidatos con certificaciones
  actualizadas.
- Boton "Guardar en local" permite descargar resultados para consulta
  offline o para poblar la base local.
- Las duraciones estan centralizadas en el PHP (un solo lugar para
  mantener), no se modifico el esquema de la BD.

F) Rol dirigido
----------------
Empresa (reclutador buscando candidatos) y Administrador (auditoria).
